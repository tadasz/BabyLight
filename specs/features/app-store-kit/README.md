# App Store kit

## What it is

The release tooling for Baby Light's App Store presence: registry-driven store metadata in 26 storefront languages, generated marketing screenshots (iPhone / iPad / Apple Watch, localized), and Python scripts that drive Xcode Cloud builds and stage/submit versions through the App Store Connect (ASC) API. It lives entirely under `AppStore/` and never ships in the app binary.

## Where it lives

Everything is under [`AppStore/`](../../../AppStore/):

- [`README.md`](../../../AppStore/README.md) — kit overview, screenshot order, pre-submit checklist.
- [`RELEASING.md`](../../../AppStore/RELEASING.md) — **the end-to-end release runbook**; read first for any staging/submission work. Also documents the ASC API gotchas the scripts already handle.
- [`METADATA.md`](../../../AppStore/METADATA.md) — copy-paste-ready English listing (name/subtitle/keywords/description/What's New), keyword research, review notes, privacy answers.
- [`LOCALIZATION.md`](../../../AppStore/LOCALIZATION.md) / [`ADD_A_LANGUAGE.md`](../../../AppStore/ADD_A_LANGUAGE.md) — how the localization pipeline works / the 4-step config-only recipe for adding a language.
- [`Makefile`](../../../AppStore/Makefile) — the entry points (`make help`); run from `AppStore/`.
- [`i18n/`](../../../AppStore/i18n/) — the localization pipeline. Single source of truth: `locales.json` (registry: `en-US` base + 26 locales), `source.json` (English), `translations/<asc>.json` (one file per language, 27 total). Scripts: `lib.py` (shared loader + validator with Apple's character limits, [lib.py:22](../../../AppStore/i18n/lib.py)), `build_catalogs.py` (generates both targets' `Localizable.xcstrings`), `screenshots.py` (localized iPhone 6.5″ renders, fonts picked per-locale by `script`), `scaffold_locale.py` (adds a language stub).
- [`asc/`](../../../AppStore/asc/) — the ASC API toolkit: `asc.py` (minimal JWT client, also a CLI for ad-hoc calls), `xcode_cloud.py` (trigger/poll Xcode Cloud builds for any branch), `push_metadata.py` (appInfo + version localizations for every store locale), `upload_screenshots.py` (three device families per locale), `stage_v11.py` (the staging orchestrator), `create_profiles.py` + `ExportOptions.plist` (local archive/signing **fallback** only — Xcode Cloud is the build path).
- [`make_screenshots.py`](../../../AppStore/make_screenshots.py) — the **English** screenshot generator (Pillow): iPhone 6.9″ set at `screenshots/`, plus `screenshots/iphone_6_5/`, `screenshots/ipad/`, `screenshots/watch/`.
- [`raw/`](../../../AppStore/raw/) — real, un-captioned simulator captures used to cross-check the mock renders.
- [`screenshots/`](../../../AppStore/screenshots/) — rendered output. `loc/<asc>/01..06.png` per locale (each with `ipad/` and `watch/` subsets), currently 25 locale folders.

## Key entry points

All `make` targets run from `AppStore/` ([Makefile](../../../AppStore/Makefile)):

| Task | Command | Governing doc |
|---|---|---|
| Validate all locales (completeness + Apple char limits) | `make validate` | `ADD_A_LANGUAGE.md` |
| Regenerate both `Localizable.xcstrings` from the registry | `make catalogs` | `LOCALIZATION.md` |
| Re-render localized screenshots (`LOCALES="de-DE fr-FR"` for a subset) | `make screenshots` | `LOCALIZATION.md` |
| Re-render the English iPhone/iPad/Watch sets | `python3 make_screenshots.py` (needs Pillow) | `AppStore/README.md` |
| Add a language (config-only) | `make add-locale ASC=.. XCODE=.. SCRIPT=.. NAME=..` | `ADD_A_LANGUAGE.md` |
| Build a branch via Xcode Cloud | `make build` / `make build-testflight` (`asc/xcode_cloud.py build-for <branch>`) | `RELEASING.md` |
| Stage the next version | `.venv/bin/python asc/stage_v11.py` | `RELEASING.md` |
| Submit for review | `.venv/bin/python asc/stage_v11.py --submit` | `RELEASING.md` |
| Ad-hoc ASC API calls | `asc/asc.py GET/POST/PATCH/DELETE <path>` | `asc.py` docstring |

**Release flow shape** ([RELEASING.md](../../../AppStore/RELEASING.md) TL;DR): merge a PR to `main` → Xcode Cloud's "AppStore" workflow auto-builds (build number = CI run number) → once the build is VALID in ASC, run `stage_v11.py` (idempotent: creates the version, pushes metadata for every store locale, uploads the three screenshot device sets per locale, attaches the highest VALID build, sets the review contact/notes, leaves it in "Prepare for Submission") → a **human** reviews the listings in ASC → `--submit`. TestFlight builds additionally need manual linking to the internal tester group ([RELEASING.md:83](../../../AppStore/RELEASING.md)).

Screenshot refresh flags: `stage_v11.py`/`upload_screenshots.py` skip device sets that already have their full count; use `--replace` to delete + re-upload, `--only <locales>` and `--device <DISPLAY_TYPE,…>` to narrow ([RELEASING.md:55](../../../AppStore/RELEASING.md)).

## Dependencies

- **The app's string catalogs are generated by this kit.** `i18n/build_catalogs.py` **overwrites** `Baby Light/Localizable.xcstrings` and `Baby Light Watch App/Localizable.xcstrings` wholesale from the registry ([build_catalogs.py:62](../../../AppStore/i18n/build_catalogs.py) — plain `json.dump`, no merge). A new user-facing string must be added to `source.json` → `ui`, every `translations/<asc>.json`, and the `IOS_KEYS`/`WATCH_KEYS` maps, or the next `make catalogs` clobbers hand edits to the catalogs. (Currently in sync: 19 iOS keys in both.)
- **Xcode Cloud is the build path.** `asc/xcode_cloud.py` hard-codes the repo and the "AppStore" / TestFlight workflow ids; the AppStore workflow is pinned to `main`, so branch builds temporarily patch the workflow's start condition and restore it. Xcode Cloud stamps `CFBundleVersion` = the run number; local edits to `CURRENT_PROJECT_VERSION` have no effect ([LOCALIZATION.md:53](../../../AppStore/LOCALIZATION.md)).
- **A local, gitignored Python venv** (`AppStore/.venv`) with PyJWT, requests, cryptography, Pillow, arabic_reshaper, python-bidi ([RELEASING.md:28](../../../AppStore/RELEASING.md)). This is tooling-only — the app targets stay zero-dependency.
- `raw/` simulator captures anchor screenshot accuracy: `render_controls_screen` is a 1:1 recreation of the SwiftUI `ControlsOverlay`, cross-checked against `raw/01_controls_red.png` ([AppStore/README.md:33](../../../AppStore/README.md)).

## Known constraints / invariants

- **Never stage or submit on the agent's own initiative.** `RELEASING.md` is the runbook; staging and submission are the owner's call (`CLAUDE.md` §3 → Git & release).
- **The registry is the single source of truth** for all store copy, screenshot captions, and in-app UI strings: `i18n/locales.json` + `source.json` + `translations/`. Adding a language touches one registry line + one translation file; `make validate` gates completeness and Apple's hard character limits ([lib.py:22](../../../AppStore/i18n/lib.py)) and must pass before shipping.
- **26-storefront-locale completeness.** `push_metadata.py` and `upload_screenshots.py` loop over every registered store locale — a locale with a translation file gets pushed; missing/over-limit fields fail `make validate`, not review.
- **`"store": false` marks an app-only language.** Lithuanian ships in the binary but is excluded from the ASC push because Apple has no `lt` storefront language; its storefront inherits en-US ([lib.py:52](../../../AppStore/i18n/lib.py)).
- **Screenshots must track the real UI.** When the app's visible UI changes, re-render **both** generators (`make_screenshots.py` for English, `i18n/screenshots.py` for the locales) and re-check against fresh `raw/` captures.
- **Credentials never enter the repo.** The key id/issuer are env-overridable defaults in `asc.py`; the `.p8` private key lives only under `~/.appstoreconnect/private_keys/` ([RELEASING.md:26](../../../AppStore/RELEASING.md)). Do not copy key material into any file here.
- **No emoji in store metadata** — ASC rejects it; source and translations stay emoji-free (`•` bullets and em-dashes are fine) ([RELEASING.md:80](../../../AppStore/RELEASING.md)).
- **The ASC API gotchas are already handled — don't re-introduce them.** Two appInfos once a version is live, auto-mirroring localizations, rejected build filters, `contactFirstName`-style review-detail field names ([RELEASING.md:66](../../../AppStore/RELEASING.md)).
- **Run the asc scripts with `.venv/bin/python`, not `make stage`** — the Makefile calls bare `python3` (Xcode's 3.9), which lacks the dependencies ([RELEASING.md:20](../../../AppStore/RELEASING.md)).
- **`stage_v11.py` is idempotent** (safe to re-run) and its `VERSION` constant must be bumped per release ([stage_v11.py:22](../../../AppStore/asc/stage_v11.py), [RELEASING.md:52](../../../AppStore/RELEASING.md)).

## Open debts

- **Language-count drift in the docs.** `AppStore/README.md` and `LOCALIZATION.md` still describe the 15-language pass ("16 total"), and `RELEASING.md` says "16 in-app languages" — the registry now has `en-US` + 26 locales. The Makefile/pipeline behaviour is registry-driven and correct; only the prose is stale.
- **`RELEASING.md` release history stops at 1.1**, and `stage_v11.py` still reads `VERSION = "1.1"` ([stage_v11.py:22](../../../AppStore/asc/stage_v11.py)) even though v1.2 was staged and submitted (commits #13/#16). How 1.2 was staged with the committed constant at 1.1 is unclear from code — presumably bumped out-of-band — confirm with owner.
- **`stage_v11.py` is misnamed**: it stages whatever `VERSION` says; it's the generic staging orchestrator, not a 1.1 one-off.
- **Thai has no localized screenshots.** `screenshots.py` gained a `thai` font entry ([screenshots.py:61](../../../AppStore/i18n/screenshots.py)) but `screenshots/loc/` has no `th/` folder (25 folders, not 26); the Thai storefront falls back to the en-US screenshots. Unclear from code whether intentional — confirm with owner.
- **en-US screenshot uploads are outside the scripts.** `upload_screenshots.py` iterates `store_locales(include_base=False)` ([upload_screenshots.py:65](../../../AppStore/asc/upload_screenshots.py)), so the English sets are not pushed by it; how they reach ASC is unclear from code (presumably uploaded manually for 1.0) — confirm with owner.
